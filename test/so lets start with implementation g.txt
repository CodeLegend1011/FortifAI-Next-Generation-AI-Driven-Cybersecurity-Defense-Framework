**Critical Decisions:**

- **Communication Protocol**: Use **gRPC** (better performance, bidirectional streaming) or **WebSocket** over TLS 1.3
- **Database**: **TimescaleDB** (PostgreSQL extension optimized for time-series data) - perfect for security logs
- **Message Queue**: **RabbitMQ** or **Redis Streams** for async processing of client data
- **GUI Framework**: **PyQt5** with **pyqtgraph** for real-time charts

**Server Features:**
- Client registration and health monitoring
- Data ingestion pipeline with validation
- Real-time threat scoring dashboard
- Manual override controls for RL actions
- Audit logging for compliance
- Role-based access control (RBAC)

```python
# Use these libraries:
- psutil: processes, CPU, memory, network connections
- pywin32: registry, WMI, event logs
- scapy: packet capture (optional, heavy)
- winreg: registry monitoring
- wmi: system info, running services
- pefile: PE file analysis
```

Linux Data Collection:
python

```python
# Use these tools:
- psutil: cross-platform process monitoring
- subprocess: netstat, lsof, iptables logs
- pyinotify: filesystem monitoring
- audit logs: /var/log/audit/audit.log parsing
```

Data Collection Strategy:
Real-time streaming (every 5-10 seconds):
* Active network connections
* New process creation/termination
* High anomaly scores from edge models
Periodic snapshots (every 5-15 minutes):
* Running processes inventory
* Registry/systemd changes
* File system modifications
* User session data
Event-driven (immediate):
* Failed login attempts (> threshold)
* Privilege escalation attempts
* New scheduled tasks/services
* Suspicious file creation in sensitive directories
Data Processing Pipeline
python

```python
# Server-side processing flow:

Client Data → Validation → Deduplication → Feature Engineering 
→ Edge Model Inference → Storage → Federated Learning Queue 
→ RL State Vector → Dashboard Update
```

Feature Engineering:
* Network: Convert IPs to numerical features (geolocation, ASN reputation scores)
* Processes: One-hot encode process names, extract parent-child relationships
* Files: Hash-based lookups (VirusTotal API), entropy calculations
* Temporal: Time-based features (hour of day, day of week, time since last event)
Privacy Considerations
Data Minimization:
* Hash sensitive strings (usernames, file paths) with HMAC-SHA256
* Send only features, not raw command lines
* Aggregate data at client side when possible
Differential Privacy:
* Add calibrated Laplacian noise to aggregated statistics
* Use ε = 1.0 to 3.0 (privacy budget) for federated learning updates

Edge Models (Client-side):
python

```python
# Lightweight models deployed to clients:

1. **Isolation Forest** (scikit-learn):
   - For process behavior (15-20 features)
   - Model size: ~500KB
   - Inference: <10ms

2. **One-Class SVM** (RBF kernel):
   - For network flow patterns
   - Pre-trained, updated weekly via federated learning

3. **Autoencoder** (PyTorch):
   - Tiny architecture: 32→16→8→16→32 neurons
   - For syscall sequences (if collected)
   - Model size: ~200KB
```

Central Models (Server-side):
python

```python
# Heavy models for deep analysis:

1. **Ensemble Autoencoder**:
   - Architecture: 128→64→32→64→128
   - Trained on normalized feature vectors
   - Reconstruction error = anomaly score

2. **LSTM for Sequence Analysis**:
   - Process execution chains
   - Network session sequences
   - 2-layer LSTM, 64 hidden units

3. **Graph Neural Network** (Optional, Week 15-16):
   - Lateral movement detection
   - Nodes = hosts, edges = network connections
   - PyTorch Geometric library

4. **XGBoost Classifier**:
   - Supervised learning on labeled incidents
   - Binary: benign/malicious
   - Feature importance for explainability
```

Model Training Strategy:
* Initial training on public datasets: KDD Cup 99, UNSW-NB15, CIC-IDS2017
* Continuous learning from labeled incidents (human feedback)
* Weekly model updates pushed to clients
